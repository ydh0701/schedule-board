# 화면 UX 재점검 및 최종 구성안

> 목표: 기존 엑셀 사용자가 낯설지 않게 업무를 입력하면서도, 팀장·PM이 일정과 인력을 판단할 수 있게 한다.  
> 원칙: 한 화면은 한 가지 주요 판단만 돕는다. 업무의 실제 입력은 항상 “업무 행/업무 편집창”에서 한다.

---

## 1. 화면 체계부터 다시 정리

현재 필요한 것은 `프로젝트 일정`과 `실무 일정`을 단순 탭으로 나누는 구조가 아니다. 사용자의 역할과 지금 하려는 행동으로 나눈다.

```text
로그인
 └─ 역할별 첫 화면
    ├─ 내 업무                 : 개인의 실행·입력 공간
    ├─ 팀 현황                 : 팀장의 배분·병목 관리 공간
    ├─ 프로젝트 현황           : PM의 전체 일정 판단 공간
    │   └─ 프로젝트 상세       : 한 프로젝트의 일정 조율 공간
    ├─ 인력 현황               : PM·팀장의 배정 판단 공간
    └─ 사용자 관리             : 관리자만의 계정·조직 관리 공간

공통으로 여는 화면
 ├─ 업무 추가 / 편집
 ├─ 담당자 변경 / 공동 담당자 추가
 ├─ 프로젝트 생성 / 편집
 ├─ 마일스톤 편집
 └─ 퇴사 처리 / 업무 재배정
```

### 반드시 지킬 구분

| 구분 | 어디서 처리하는가 | 이유 |
|---|---|---|
| 업무 입력·수정·완료 | 내 업무의 행, 업무 편집창 | 개인 엑셀의 입력 흐름을 유지 |
| 한 프로젝트의 일정 관계 확인 | 프로젝트 상세 일정표 | PM과 팀장이 조율할 때만 필요 |
| 사람의 여유 판단 | 인력 현황 또는 담당자 변경창 | 배정 전 판단이 목적 |
| 계정·역할·퇴사 | 사용자 관리 | 실무 일정 화면과 분리 |

## 2. 로그인 및 접근 상태

### 사용자 목적

“내 회사 계정으로 들어가서 바로 내 일을 보고 싶다.”

### 첫 화면에 필요한 UI

```text
                [STORYTACO 로고]
                 사내 일정 관리
       프로젝트와 실무 일정을 한곳에서 관리합니다.

               [ Google 계정으로 로그인 ]
```

### 필요한 기능

- Google 로그인
- 로그인 세션 유지
- 로그인 뒤 역할·관리자 권한·재직 상태를 읽어 첫 화면으로 이동

### 상태별 화면

| 상태 | 사용자에게 보여줄 문구 | 가능한 행동 |
|---|---|---|
| 승인됨 | 별도 안내 없이 역할별 첫 화면 이동 | 서비스 사용 |
| 계정 정보 없음 | `계정 설정이 완료되지 않았습니다. 관리자에게 역할과 팀 배정을 요청해주세요.` | 로그아웃 |
| 비활성/퇴사 | `현재 사용할 수 없는 계정입니다.` | 로그아웃 |
| 네트워크/권한 오류 | `계정 정보를 불러오지 못했습니다.` | 다시 시도, 로그아웃 |

### UX 점검

- UID, 확인 코드, Firestore 같은 기술 용어는 절대 보이지 않는다.
- 로그인 카드는 화면 가운데에 충분한 크기로 두되, 상단 헤더를 따로 만들지 않는다. 로그인 전에는 헤더가 불필요하다.

## 3. 역할별 첫 진입과 전역 메뉴

### 사용자 목적

로그인 후 메뉴를 해석하지 않고 바로 지금 해야 할 일을 본다.

### 기본 진입

| 사용자 | 첫 화면 | 첫 화면에서의 질문 |
|---|---|---|
| 팀원 | 내 업무 | 오늘 무엇을 해야 하나? |
| 팀장 | 팀 현황 | 우리 팀에 막힌 일·과부하가 있나? |
| PM | 프로젝트 현황 | 어떤 프로젝트가 위험한가? |
| 관리자만 있는 계정 | 사용자 관리 | 새 계정과 조직 설정이 필요한가? |

PM이나 팀장이 관리자이기도 하면, 업무 역할에 따른 첫 화면을 먼저 열고 `사용자 관리`는 메뉴로 둔다.

### 전역 헤더

```text
STORYTACO 일정 관리    내 업무 | 팀 현황 | 프로젝트 | 인력 현황     윤도헌 · PM  [☾] [로그아웃]
```

- 메뉴는 권한이 있는 것만 표시한다.
- 현재 메뉴는 색상뿐 아니라 밑줄/굵기로 표시한다.
- 헤더에 대시보드 숫자나 큰 버튼을 넣지 않는다. 본문에만 둔다.

### 홈 화면

홈 아이콘 또는 로고를 눌렀을 때만 큰 선택 카드 화면을 제공한다.

```text
무엇을 관리할까요?
[내 업무] [프로젝트 현황] [팀·인력 현황]
```

매 로그인 직후 이 선택 화면을 거치게 하면 팀원의 하루 시작이 한 단계 늘어난다. 따라서 기본 진입은 역할별 화면이어야 한다.

## 4. 내 업무 — 개인의 실행 화면

### 사용자와 목적

- 사용자: 팀원, 팀장, PM
- 목적: 오늘 할 업무를 확인하고, 엑셀 개인 업무표처럼 한 줄 단위로 추가·수정·완료한다.
- 이 화면에서 답해야 할 질문: **오늘 무엇을 해야 하고, 언제까지 끝내야 하는가?**

### 절대 넣지 않을 것

- 전체 팀 인력 현황
- 전체 프로젝트의 긴 타임라인
- 사용자 관리
- 팀원이 조작할 수 없는 다른 사람의 상세 업무 편집

### 화면 배치

```text
내 업무                                                     [+ 업무 추가]
오늘 4개 · 이번 주 마감 7개 · 지연 1개

[오늘] [이번 주] [이번 달] [전체]       [프로젝트 ▼] [상태 ▼] [검색]
─────────────────────────────────────────────────────────────────────
프로젝트   업무                              기간        상태      담당
PC12M      데모 UI 프리뷰·연출                9/16–9/21   진행 중   윤도헌
           UI · 데모 준비                     D-3 · 정상
─────────────────────────────────────────────────────────────────────
PC12       화면 기획 확정                    9/14–9/16   차단      박지현
           기획 · 데모 준비                   사유: 기획 검토 대기
```

### 상단 정보

- `오늘 n개`: 오늘 날짜에 걸린 미완료 업무
- `이번 주 마감 n개`: 이번 주 마감인 미완료 업무
- `지연 n개`: 마감일이 지났고 완료되지 않은 업무
- 요약 수치는 누르면 해당 목록 필터로 바뀐다.

### 업무 행의 정보 우선순위

| 우선 | 정보 | 표현 |
|---|---|---|
| 1 | 프로젝트·플랫폼 | `PC12`, `PC12M`, `PC12C` 뱃지 |
| 2 | 업무명 | 가장 큰 텍스트 |
| 3 | 직군·업무 묶음 | 업무명 아래 보조 텍스트 |
| 4 | 기간 / 남은 일수 | `9/16–9/21 · D-3` |
| 5 | 실제 상태 / 일정 상태 | `진행 중`, `정상`처럼 두 상태를 분리 |
| 6 | 담당자 | 공동 담당 포함, 필요할 때만 |

### 행에서 가능한 행동

- 행 클릭: 업무 편집 패널 열기
- 완료 체크: 즉시 완료, 완료 시각 기록
- 상태 변경: 예정 / 진행 중 / 차단됨
- 담당자 칩 클릭: 담당자 변경·공동 담당자 추가
- 링크 아이콘: 등록된 참고 링크 열기

### 업무 추가 흐름

`+ 업무 추가` → 공통 업무 편집 패널 → 저장 → 목록의 알맞은 기간 탭에 즉시 표시

### 필터와 정렬

- 기본 정렬: 지연 → 오늘 마감 → 가까운 마감 → 나머지
- 필터: 프로젝트, 플랫폼, 직군, 실제 상태, 일정 상태, 담당 여부
- 완료 업무는 기본 숨김, 필요할 때 `완료 포함`으로 켠다.

### 빈 상태와 예외

| 경우 | 표시 | 행동 |
|---|---|---|
| 오늘 업무 없음 | `오늘 해야 할 업무가 없습니다.` | 이번 주 보기 |
| 프로젝트에 아직 참여하지 않음 | `참여 중인 프로젝트가 없습니다.` | PM/팀장에게 프로젝트 배정을 요청하라는 안내만 표시 |
| 저장 실패 | 작성한 값 유지 | 재시도 |
| 다른 사람이 방금 변경 | 최신 값 알림, 충돌 항목 강조 | 새로고침 또는 내 변경 다시 적용 |

## 5. 업무 편집 패널 — 모든 입력의 단일 창구

### 목적

같은 업무를 어느 화면에서 열어도 같은 방법으로 수정한다. 프로젝트 화면과 내 업무 화면이 다른 입력 방식을 쓰면 안 된다.

### 배치

데스크톱은 오른쪽 패널, 모바일은 전체 화면 모달이다.

```text
업무 수정                                                   [×]
기본 정보
프로젝트 [PC12 ▼]  플랫폼 [모바일 ▼]  직군 [UI ▼]
업무 묶음 [데모 준비 ▼]
업무명   [데모 UI 프리뷰·연출                         ]

일정
시작일 [2026-09-16]  예상 워킹데이 [3]  마감일 [2026-09-18]
일정 상태: 정상 · 주말/공휴일 제외 계산

진행
실제 상태 [진행 중 ▼]   완료 체크 [ ]

세부 정보 (직군별)
빌드 버전 [데모 ▼]  시스템/화면 [상점 UI              ]

비고 / 링크
[메모]  [링크 추가]

담당자
윤도헌 (주 담당)  [+ 공동 담당자]  [담당자 변경]

[삭제/보관]                                  [취소] [저장]
```

### 입력 규칙

| 필드 | 규칙 |
|---|---|
| 프로젝트, 플랫폼, 직군, 업무명 | 필수 |
| 시작일, 워킹데이 | 필수. 워킹데이는 0보다 커야 함 |
| 마감일 | 자동 계산 기본값. 직접 바꾸면 워킹데이 재계산을 확인 |
| 실제 상태 | 사용자가 선택 |
| 일정 상태 | 시스템 계산, 사용자가 수정하지 않음 |
| 시스템/빌드 버전 | UI·개발·QA 등 필요한 직군에서만 노출 |
| 비고/링크 | 선택 |

### 검증 UI

- 저장 버튼을 눌렀을 때 누락 필드는 붉은 테두리, 해당 칸 아래 원인 문구, 첫 오류 필드로 자동 이동.
- 입력하지 않은 상태로 저장해도 업무는 생성되지 않는다.
- 저장 중에는 중복 클릭을 막는다.

### 삭제와 보관

- 진행 중 업무는 즉시 삭제보다 `보관`을 우선한다.
- 완료 업무는 보관 가능하되, 프로젝트 진행률 계산의 기준은 유지한다.
- 완전 삭제는 PM/관리자만, 확인 모달을 거친다.

## 6. 담당자 변경 / 공동 담당자 추가 — 배정 확정 화면

### 사용자 목적

구두로 조율한 뒤, “누가 이 일을 맡는지”를 즉시 확정한다. 대상자가 실제로 받을 수 있는지 확인한다.

### 열리는 지점

- 내 업무의 담당자 칩
- 업무 편집 패널의 `담당자 변경`
- 팀 현황과 인력 현황의 `배정`
- 프로젝트 상세의 미배정 업무

### 배치와 정보

```text
담당자 배정
PC12M · 데모 UI 프리뷰·연출 · 3 워킹데이 · 마감 9/21

방식: [주 담당자 변경] [공동 담당자 추가] [미배정으로 변경]
대상자: [이름, 팀, 직군으로 검색                           ]

윤도헌 · 기획팀 · 기획
진행 프로젝트  PC12  PC12M
이번 주 업무량  40% · 여유
다음 가능일     9/03
판정            마감일 내 완료 가능

[취소]                                             [배정 저장]
```

### 가용성 판단 상세

1. 대상자의 완료되지 않은 업무를 읽는다.
2. 업무별 시작·마감 기간에 예상 워킹데이를 배분한다.
3. 사용자별 주간 가능 업무량과 비교한다.
4. 주말·국가 공휴일을 제외해 다음 가능일과 완료 예상일을 계산한다.
5. 새 업무를 넣었을 때의 결과를 표시한다.

| 결과 | 보여줄 UI | 저장 방식 |
|---|---|---|
| 여유 | `이번 주 40% · 마감일 내 완료 가능` | 일반 `배정 저장` |
| 주의 | `이번 주 80% · 기존 업무 1건과 겹침` | 노랑 경고를 읽은 뒤 저장 |
| 과부하 | `마감일 2일 초과 예상 · 진행 업무 3건` | `그래도 배정` 버튼을 별도 표시 |
| 계산 불가 | 워킹데이·마감일이 없는 기존 업무 수 표시 | 확정 전 일정 정보 보완 요구 |

### 저장 결과

- 새 담당자의 내 업무에 즉시 나타난다.
- 기존 주 담당자의 내 업무에서는 이관 시 사라지고, 공동 담당이면 유지된다.
- 프로젝트 상세, 팀 현황, 인력 현황의 수치도 실시간 갱신한다.
- 변경 이력에 전/후 담당자, 변경자, 시각, 과부하 경고 확인 여부를 남긴다.

### 권한

- 팀원: 자신이 주 담당인 업무에만 이관/공동 담당 추가
- 팀장: 자기 팀 또는 맡은 프로젝트 범위
- PM: 전체 프로젝트
- 관리자: 전체 범위

## 7. 팀 현황 — 팀장의 판단 화면

### 사용자와 목적

- 사용자: 팀장, PM
- 질문: **우리 팀에서 오늘 막힌 곳은 어디고, 누구에게 일을 옮길 수 있는가?**

### 절대 넣지 않을 것

- 모든 프로젝트의 상세 일정표
- 팀원 개인의 불필요한 완료 업무 전체
- 휴가·병가 관리

### 화면 배치

```text
기획팀 현황                                     [팀 ▼] [직군 ▼] [프로젝트 ▼]
오늘 마감 3 | 지연·차단 2 | 과부하 1명 | 미배정 4

이름        프로젝트             진행 업무  이번 주 업무량  다음 가능일  위험
윤도헌      [PC12] [PC12M]       5          72% 보통        9/04         0
박지현      [PC12] [PC14]        7          105% 과부하     9/10         지연 1
```

### 상단 요약의 기능

- 요약 카드를 누르면 같은 화면의 목록 필터가 바뀐다.
- 수치가 0인 정상 항목은 눈에 덜 띄게 처리하고, 위험 항목만 강조한다.

### 팀원 행 확장

행 클릭 시 아래로 펼친다.

- 이번 주·다음 3주 업무량 막대
- 현재 업무와 예정 업무
- 지연/차단 업무
- 해당 팀원에게 업무 배정
- 해당 팀원의 참여 프로젝트로 이동

### 필터와 권한

- 팀장은 자기 팀이 기본 선택·고정된다.
- PM은 팀을 바꿔 전체를 비교할 수 있다.
- 팀장은 다른 팀원 업무의 상세를 열 수 있어도, 권한 밖 직군의 일정·담당자 변경은 제한한다.

### 빈 상태

- 팀에 활성 인원이 없을 때: 조직 설정이 필요함을 표시
- 필터 결과 없음: 필터 초기화

## 8. 프로젝트 현황 — PM의 우선순위 결정 화면

### 사용자와 목적

- 사용자: PM, 팀장(제한된 목록), 팀원(참여 프로젝트 읽기 중심)
- 질문: **지금 어떤 프로젝트를 먼저 봐야 하는가?**

### 화면 배치

```text
프로젝트 현황                                             [+ 프로젝트 생성]
전체 10 | 정상 7 | 주의 2 | 지연 1 | 완료 0
[플랫폼 ▼] [담당 PM ▼] [상태 ▼]                           [프로젝트 검색]

PC12   하천의2 DLC   [PC] [모바일] [콘솔]      정상 · 62%
다음: 데모 빌드 마감 2026-10-01 · D-24
기획 정상 | UI 주의 | 개발 정상 | QA 미배정                         [상세 보기]
```

### 프로젝트 한 줄에 필요한 데이터

| 정보 | 필요한 이유 |
|---|---|
| 코드·이름·플랫폼 | 무엇을 다루는 프로젝트인지 즉시 식별 |
| 일정 건강 상태 | PM의 우선순위 판단 |
| 완료율 | 전체 진행 정도 파악 |
| 다음 마일스톤·D-day | 다음 조율 시점 판단 |
| 지연·차단·미배정 수 | 문제의 종류와 크기 파악 |
| 직군별 요약 | 어느 직군에서 병목인지 파악 |

### 프로젝트 건강 상태 계산

- 지연 업무가 있거나 다음 고정 마일스톤을 지킬 수 없으면 `지연`
- 지연은 아니지만 차단·미배정·과부하 위험이 있으면 `주의`
- 그 외는 `정상`
- 완료 업무만 남으면 `완료`

### 주요 기능

- 프로젝트 생성
- 필터, 검색, 상태별 정렬
- 상세 이동
- PM만 프로젝트 보관·기본 정보 편집

### 하지 않는 기능

프로젝트 카드에서 업무를 직접 열 개씩 수정하지 않는다. 상세 화면으로 이동시킨다.

## 9. 프로젝트 생성 / 기본 정보 편집

### 목적

프로젝트의 고정 기준을 먼저 잡고, 생성 직후 해야 할 다음 행동을 안내한다.

### 입력 UI

```text
프로젝트 생성
프로젝트 코드 [PC20       ]
프로젝트명   [프로젝트명 입력                         ]
플랫폼       [PC] [모바일] [콘솔] [공통]
담당 PM      [신예지나 ▼]
시작 기준일  [2026-09-01]
설명·메모    [선택 입력]

[취소] [프로젝트 만들기]
```

### 검증

- 코드와 이름은 필수, 코드 중복 불가
- 플랫폼 최소 하나 선택
- PM 미지정은 경고하되, 임시 프로젝트라면 미배정 저장 가능

### 생성 성공 뒤 화면

프로젝트 상세로 이동하되 다음 안내를 표시한다.

1. 마일스톤 추가
2. 플랫폼별 담당자 지정
3. 업무 추가 또는 템플릿 적용

프로젝트 생성 시 임의의 더미 업무는 자동 생성하지 않는다.

## 10. 프로젝트 상세 — 일정 조율 화면

### 사용자와 목적

- 사용자: PM, 팀장, 참여 팀원
- 질문: **이 프로젝트에서 어떤 직군의 어떤 일이 언제 충돌하거나 비어 있는가?**

### 상단 배치

```text
PC12 · 하천의2 DLC     [정상]     [프로젝트 정보 수정]
PC | 모바일 | 콘솔
다음 마일스톤  데모 빌드 마감 · 2026-10-01 · D-24

플랫폼별 담당자
PC      기획 윤도헌 · UI 박지현 · 개발 김개발
모바일  기획 이기획 · UI 최UI · 개발 김개발B
콘솔    미배정
```

플랫폼별 담당자는 별도 큰 카드로 빼지 않는다. 프로젝트 제목 우측의 빈 공간을 사용한다.

### 위험 요약 — 상단 바로 아래

```text
⚠ 확인 필요: 지연 2 · 차단 1 · 미배정 3 · UI 과부하 1명
[지연 보기] [미배정 보기] [인력 배정]
```

- 위험이 0이면 접거나 표시하지 않는다.
- 경고 수치를 누르면 아래 전체 업무 탭에 필터가 걸린다.

### 본문 탭

| 탭 | 목적 | 기본 사용자 |
|---|---|---|
| 일정 조율 | 날짜와 직군의 관계·충돌 확인 | PM·팀장 |
| 전체 업무 | 행 단위 검색·수정·배정 | 모두 |
| 마일스톤 | 고정 기준일과 연결 업무 확인 | PM·팀장 |
| 변경 이력 | 왜 일정/담당이 바뀌었는지 확인 | PM·팀장, 팀원은 자기 업무 범위 |

### 일정 조율 탭

```text
[일 단위] [주 단위] [이전] 2026년 9월 [다음]             [직군 필터]

날짜        | 마일스톤 | 기획 | UI | 개발 | 글비 | 영상 | 제작실 | QA
9/14 (월)   | 데모 기획 확정 | 기능 기획 |     |     |      |      |      |
9/16 (수)   |            |          | UI 디자인 | |   |      |      |      |
```

- **왼쪽은 날짜, 위쪽은 직군**으로 고정한다.
- 날짜 열과 상단 직군 헤더는 스크롤 시 고정한다.
- 오늘은 세로 강조선, 주말·공휴일은 옅은 배경.
- 한 업무는 시작일부터 마감일까지 이어진 막대로 표시하되, 짧은 제목·상태색·담당자 약자로 식별한다.
- 같은 날짜·직군에 업무가 여러 개면 `+2`로 접고 클릭하면 목록을 연다.
- 빈 셀 클릭: 해당 날짜·직군이 미리 채워진 업무 편집 패널.
- 업무 막대 클릭: 업무 편집 패널.
- 이 표에서 장문의 업무명 직접 타이핑은 하지 않는다.

### 전체 업무 탭

프로젝트 안의 업무를 내 업무와 같은 행 구조로 보여 준다. 차이는 담당자·플랫폼·직군을 모두 볼 수 있다는 점이다.

- 필터: 플랫폼, 직군, 담당자, 실제 상태, 일정 상태, 마일스톤
- PM/팀장: 배정·재배정
- 팀원: 자기 업무만 편집, 다른 업무는 보기만 가능

### 마일스톤 탭

| 정보 | 기능 |
|---|---|
| 마일스톤명·날짜·플랫폼 | 고정 기준일 식별 |
| 진행 상태 | 연결 업무 기준으로 계산 |
| 연결 업무 | 클릭해 업무 목록 필터 |
| 위험 | 마감 이후 완료 예상 업무 수 |

### 변경 이력 탭

`9/01 윤도헌이 UI 디자인의 담당자를 박지현 → 김UI로 변경 · 과부하 경고 확인`처럼 사람이 읽을 수 있는 문장으로 표시한다.

## 11. 마일스톤 편집

### 사용자 목적

데모·완전판 출시 등 고정 날짜를 바꾸었을 때 어떤 업무가 영향을 받는지 안다.

### 입력

- 이름, 날짜, 플랫폼/공통, 고정 여부, 설명

### 날짜 변경 확인 화면

```text
데모 빌드 마감을 10/01 → 10/08로 변경합니다.
연결 업무 12건 중 4건의 마감일이 함께 재계산됩니다.
지연 위험 업무: 1건 → 0건 예상

[취소] [변경 저장]
```

마일스톤 날짜를 바꾼다고 모든 업무 날짜를 무조건 밀지 않는다. 연결 규칙이 있는 업무만 재계산 대상이며, 수동 마감 업무는 별도 표시한다.

## 12. 인력 현황 — 배정 후보 비교 화면

### 사용자와 목적

- 사용자: PM, 팀장
- 질문: **이 업무를 누구에게 주면 마감일을 지키고 과부하가 적은가?**

### 화면 배치

```text
인력 현황
전체 18 | 여유 6 | 보통 9 | 과부하 3
[팀 ▼] [직군 ▼] [참여 프로젝트 ▼] [가용 상태 ▼]          [이름 검색]

이름       팀/직군      프로젝트             진행  이번 주     다음 가능일    [배정]
윤도헌     기획팀/기획   [PC12] [PC12M]      5     72% 보통    9/04
박지현     UI팀/UI       [PC12] [PC14]       7     105% 과부하 9/10
```

### 뱃지 규칙

- 연한 뱃지: 참여 중이지만 현재 미완료 업무가 없는 프로젝트
- 진한 뱃지: 현재 미완료 업무가 있는 프로젝트
- 플랫폼은 프로젝트 코드 뒤에 붙인다. 예: `PC12`, `PC12M`, `PC12C`
- 뱃지가 많으면 두 개까지만 보이고 `+3`으로 접는다.

### 행 확장 정보

- 현재 업무와 예정 업무
- 4주 업무량: 주별 막대와 과부하 구간
- 직군/플랫폼 경험 정보
- 선택한 업무를 가정했을 때의 완료 예상일
- `이 사람에게 배정` 버튼

### 가용성의 한계도 UI에 표시

현재 도구는 휴가·연차·병가를 관리하지 않으므로, “개인 사정까지 반영한 확정 가용성”이 아니라 **등록된 업무 기준의 일정상 가용성**임을 작은 안내로 표시한다.

## 13. 사용자 관리 — 관리자 전용

### 사용자와 목적

- 사용자: 관리자
- 질문: **누가 어떤 권한·팀·직군으로 이 도구를 쓰는가? 퇴사 업무는 어떻게 넘길 것인가?**

### 화면 배치

```text
사용자 관리
승인 대기 2 | 활성 18 | 비활성 3
[상태 ▼] [업무 역할 ▼] [팀 ▼] [직군 ▼]                    [이름/이메일 검색]

이름      이메일              업무 역할  관리자  팀/직군      상태          [편집]
윤도헌    ydh@storytaco.com   PM         예       기획팀/기획   활성
```

### 사용자 편집 패널

- 업무 역할: PM / 팀장 / 팀원
- 시스템 관리자 여부: 별도 토글
- 팀, 직군
- 활성/비활성
- 재직/퇴사 상태

### 퇴사 처리 흐름

1. 사용자 비활성화 전에 진행·예정 업무를 계산한다.
2. 업무마다 새 담당자, 공동 담당 유지, 미배정 중 하나를 고른다.
3. 대상자별 가용성 경고를 동일하게 제공한다.
4. 처리 결과를 확인한 뒤 퇴사자를 비활성화한다.
5. 과거 완료 업무·기록은 이름 그대로 보존한다.

퇴사자는 새 업무·새 배정 대상자 목록에서는 제외한다.

## 14. 공통 상태와 누락되기 쉬운 기능

### 실시간 갱신

누군가 업무의 상태·기간·담당자를 바꾸면 다음 화면은 새로고침 없이 갱신된다.

- 담당자 본인의 내 업무
- 이전 담당자의 내 업무
- 프로젝트 상세
- 프로젝트 현황의 위험/진행률
- 팀 현황과 인력 현황의 업무량·다음 가능일

### 반드시 있는 상태

| 상태 | 필요한 UI |
|---|---|
| 로딩 | 표/카드 모양의 스켈레톤. 빈 화면처럼 보이면 안 됨 |
| 데이터 없음 | 이유별 안내와 다음 행동 버튼 |
| 저장 중 | 버튼 비활성 + 진행 문구 |
| 저장 실패 | 입력값 유지 + 실패 이유 + 재시도 |
| 권한 없음 | 숨긴 버튼 + 직접 접근 시 안내 |
| 동시 수정 | 최신 변경 내용을 안내하고 충돌 항목을 비교 |
| 과부하 배정 | 경고 이유·그래도 배정·이력 기록 |

### 알림 문구 원칙

- 성공: `업무를 윤도헌에게 배정했습니다.`
- 주의: `윤도헌은 이번 주 업무량이 80%입니다.`
- 과부하: `배정하면 마감일을 2일 초과할 수 있습니다.`
- 실패: `저장하지 못했습니다. 입력한 내용은 유지됩니다.`

### 최종 구현 우선순위

1. 로그인·권한과 역할별 메뉴
2. 내 업무 + 공통 업무 편집 패널
3. 담당자 변경 + 가용성 경고 + 실시간 갱신
4. 프로젝트 현황 + 프로젝트 상세의 전체 업무 탭
5. 팀 현황 + 인력 현황
6. 일정 조율 표, 마일스톤 영향 계산
7. 사용자 관리와 퇴사 재배정
