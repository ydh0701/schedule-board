# 화면 설계 상세

> 작성: 2026-08-24  
> 기준: `업무흐름_기반_재설계.md`  
> 범위: 실제 구현 시 화면·모달·권한·빈 상태를 빠뜨리지 않기 위한 화면 명세

## 0. 공통 규칙

### 역할과 노출 범위

| 구분 | 설명 |
|---|---|
| 관리자 | 시스템 권한. 사용자·조직·권한을 관리한다. PM·팀장·팀원 역할과 별도다. |
| PM | 전체 프로젝트·인력·일정을 조율한다. |
| 팀장 | 자기 팀의 인력·업무와 참여 프로젝트를 조율한다. |
| 팀원 | 자기 업무와 참여 프로젝트를 확인·수정한다. |

### 공통 레이아웃

```text
┌──────────────────────────────────────────────────────────────┐
│ STORYTACO 일정 관리 | 역할별 메뉴              사용자 · 설정 │
├──────────────────────────────────────────────────────────────┤
│ 페이지 제목 / 설명                              주요 행동 버튼 │
│ 필터 · 검색 · 기간 선택                                         │
├──────────────────────────────────────────────────────────────┤
│ 화면별 본문                                                     │
└──────────────────────────────────────────────────────────────┘
```

- 상단 바는 고정하고 높이를 낮게 유지한다.
- 주요 행동 버튼은 페이지당 하나만 강조색으로 쓴다. 예: `+ 업무 추가`, `+ 프로젝트 생성`.
- 상태는 색만으로 표현하지 않는다. `정상`, `주의`, `지연`, `차단` 텍스트를 함께 쓴다.
- 날짜 계산은 주말·국가 공휴일만 제외한다. 휴가·연차·병가는 저장·표시·계산하지 않는다.
- 모든 목록은 로딩, 데이터 없음, 권한 없음, 저장 실패 상태를 각각 제공한다.

## 1. 로그인 / 최초 접근 화면

### 목적

Google 로그인과 계정 접근 상태를 명확하게 보여 준다.

### 화면 구성

1. 중앙 브랜드 영역: STORYTACO 로고, `사내 일정 관리`, 짧은 서비스 설명
2. `Google 계정으로 로그인` 버튼
3. 로그인 뒤 상태별 화면
   - 정상 계정: 역할별 첫 화면으로 즉시 이동
   - 미배정 계정: `계정 설정 중` 안내와 로그아웃
   - 비활성·퇴사 계정: 접근 불가 안내와 로그아웃
   - 오류: 재시도 버튼과 이해 가능한 오류 문구

### 표시하지 않을 것

- Firebase UID, 확인 코드 등 기술 정보
- 권한 문서를 찾을 수 없다는 내부 용어

## 2. 홈 / 역할별 진입 화면

### 목적

현재 역할에 맞는 주요 공간으로 빠르게 이동시킨다. 매 로그인마다 선택을 강요하지 않는다.

### 기본 이동

| 역할 | 기본 진입 |
|---|---|
| 팀원 | 내 업무 |
| 팀장 | 팀 현황 |
| PM | 프로젝트 현황 |
| 관리자만 보유 | 사용자 관리 |

### 홈 버튼을 눌렀을 때

큰 선택 카드 2~3개만 제공한다.

- `내 업무`: 오늘·이번 주 해야 할 일
- `프로젝트 관리`: 참여 프로젝트 또는 전체 프로젝트
- 팀장·PM만 `인력/팀 현황`

카드는 단순 탭이 아니라 해당 화면으로 이동하는 진입 카드다.

## 3. 내 업무

### 사용자와 목적

- 사용자: 팀원, 팀장, PM
- 목적: 개인이 오늘 해야 할 일과 예정 업무를 엑셀 개인 시트보다 빠르게 확인·등록·완료한다.

### 상단 구성

```text
내 업무                                               + 업무 추가
오늘 4 | 이번 주 12 | 이번 달 28 | 전체
[프로젝트] [플랫폼] [직군] [실제 상태] [일정 상태]      검색
```

- 기간 탭은 기본으로 `오늘`을 선택한다.
- 프로젝트·플랫폼·상태 필터는 동시에 적용한다.
- 검색은 프로젝트 코드, 업무명, 시스템, 비고를 대상으로 한다.

### 업무 목록

한 행이 한 업무다. 모바일에서는 세부 열을 보조 줄로 접는다.

| 열 | 내용 | 행동 |
|---|---|---|
| 프로젝트 | `PC12`, `PC12M` 등 뱃지 | 프로젝트 상세 이동 |
| 업무 | 업무 묶음 / 업무명 | 행 클릭 시 편집 |
| 기간 | 시작일, 마감일, 워킹데이 | 일정 확인 |
| 실제 상태 | 예정 / 진행 중 / 차단 / 완료 | 빠른 상태 변경 |
| 일정 상태 | 예정 / 정상 / 임박 / 지연 | 자동 계산, 수정 불가 |
| 담당 | 주 담당자와 공동 담당자 | 담당자 변경 열기 |
| 더보기 | 링크·비고·이력 | 상세 메뉴 |

### 주요 기능

- 업무 추가
- 업무 수정
- 완료 체크와 완료 취소
- 차단 사유 입력
- 담당자 변경 또는 공동 담당자 추가
- 참고 링크 추가·열기
- 내 업무에서 제거: 담당자 이관 또는 완료/보관으로만 가능

### 빈 상태

- 오늘 할 일이 없을 때: `오늘 등록된 업무가 없습니다. 이번 주 업무 보기` 버튼
- 필터 결과가 없을 때: 적용된 필터를 보여 주고 `필터 초기화` 버튼

### 권한

- 팀원: 본인이 담당자인 업무 수정·완료·이관 가능
- 팀장·PM: 보이는 범위의 업무 수정·배정 가능
- 완료 업무는 일반 수정 대신 `재개` 확인 후 변경

## 4. 업무 추가 / 업무 편집 패널

### 목적

모든 화면에서 같은 형식으로 업무를 만들고 수정한다. 화면별로 다른 입력 폼을 만들지 않는다.

### 열리는 위치

- 데스크톱: 오른쪽 슬라이드 패널
- 좁은 화면: 전체 화면 모달

### 입력 순서

1. 프로젝트
2. 플랫폼
3. 직군
4. 업무 묶음과 업무명
5. 시작일과 예상 워킹데이
6. 자동 계산된 마감일
7. 실제 상태, 비고, 링크
8. 담당자

### 직군별 확장 필드

| 직군 | 선택 확장 필드 |
|---|---|
| 기획 | 기능 분류, 시스템 |
| UI | 빌드 버전, 시스템/화면 |
| 개발 | 기능 분류, 구현 영역 |
| QA | 테스트 범위, 빌드 버전 |
| 영상·글비·제작실 | 산출물 유형, 협업처 |

### 검증

- 프로젝트, 업무명, 시작일, 예상 워킹데이는 필수다.
- 워킹데이는 0보다 커야 한다.
- 마감일은 직접 바꿀 수 있지만, 변경하면 워킹데이 재계산 여부를 확인한다.
- 저장 전 누락 필드는 붉은 테두리·필드 아래 설명으로 표시한다.

### 저장 후 동작

- Firestore 저장 성공: 목록과 프로젝트 상세·인력 현황을 실시간 갱신
- 실패: 입력값은 유지하고, 실패 이유와 재시도 버튼 표시
- 저장 중: 중복 저장을 막고 버튼에 진행 상태 표시

## 5. 담당자 변경 / 공동 담당자 추가 모달

### 목적

구두로 합의한 배정을 시스템에 확정하고, 대상자의 가용성을 먼저 판단한다.

### 구성

```text
업무: PC12 · 상점 UI 디자인
방식: (주 담당자 변경) (공동 담당자 추가) (담당자 비우기)
대상자: [이름 또는 팀·직군 검색]

가용성 결과
이번 주 40% · 다음 가능일 9/03 · 마감일 내 완료 가능

[취소] [배정 저장]
```

### 가용성 판정

| 상태 | 기준 | UI와 행동 |
|---|---|---|
| 여유 | 지정 기간 업무량이 기준 이하 | 초록 안내, 일반 저장 버튼 |
| 주의 | 일정 일부 겹침 또는 업무량 경계 | 노랑 안내, 확인 문구 후 저장 |
| 과부하 | 업무량 초과 또는 마감일 이후 완료 예상 | 빨강 안내, `그래도 배정`을 별도 클릭해야 함 |

### 필수 기록

- 이전 담당자와 새 담당자
- 주/공동 담당 변경 방식
- 변경한 사람과 시각
- 과부하 경고 표시 여부와 확인 사유

### 권한

- 팀원: 본인 주 담당 업무만 이관·공동 담당 추가 가능
- 팀장: 자기 팀 업무와 참여 프로젝트 업무
- PM: 전체 프로젝트 업무
- 관리자: 업무 역할 범위 외에도 전체 수정 가능

## 6. 팀 현황

### 사용자와 목적

- 사용자: 팀장, PM
- 목적: 팀장이 팀 병목과 인력 여유를 하루 단위로 파악하고 재배정한다.

### 상단 요약

| 카드 | 수치 | 클릭 시 |
|---|---|---|
| 오늘 마감 | 오늘 마감 미완료 업무 수 | 해당 업무 필터 |
| 지연·차단 | 지연 또는 차단 업무 수 | 위험 업무 목록 |
| 과부하 인원 | 이번 주 기준 초과 인원 수 | 과부하 인력 필터 |
| 미배정 | 팀 직군 관련 미배정 업무 수 | 미배정 목록 |

### 인력 목록

| 열 | 내용 |
|---|---|
| 이름 / 직군 | 팀원 식별 |
| 프로젝트 | 연한 참여 뱃지, 진한 진행 뱃지 |
| 진행 업무 | 미완료 업무 수 |
| 이번 주 업무량 | 수치·막대·상태 텍스트 |
| 다음 가능일 | 주말·공휴일 제외 계산 |
| 위험 | 지연·차단 업무 수 |

### 행 확장 영역

- 현재와 예정 업무 목록
- 4주 업무량 막대
- 업무 이관·공동 담당자 추가 버튼
- 해당 팀원의 참여 프로젝트 이동

### 필터

직군, 업무량 상태, 프로젝트, 위험 업무 포함 여부

### 빈 상태

팀원이 아직 없으면 팀 구성 안내와 사용자 관리 이동 버튼을 보인다.

## 7. 프로젝트 현황

### 사용자와 목적

- 사용자: PM, 팀장(참여 범위 또는 소속 범위), 팀원(참여 프로젝트 읽기 전용 목록)
- 목적: PM이 프로젝트 위험과 다음 의사결정 대상을 빠르게 고른다.

### 상단 구성

```text
프로젝트 현황                                     + 프로젝트 생성
전체 | 정상 | 주의 | 지연 | 완료
[플랫폼] [담당 PM] [상태]                          검색
```

### 프로젝트 행 / 카드

한 프로젝트를 넓은 가로 행으로 표시하고, 작은 화면에서 카드로 변환한다.

| 영역 | 내용 |
|---|---|
| 식별 | 프로젝트 코드, 이름, 플랫폼 뱃지 |
| 건강 상태 | 정상 / 주의 / 지연 |
| 진행 | 완료율, 완료/전체 업무 수 |
| 다음 일정 | 다음 마일스톤, 남은 워킹데이 |
| 위험 | 지연·차단·미배정 수 |
| 직군 상태 | 기획·UI·개발·QA 등 요약 뱃지 |

### 주요 기능

- 프로젝트 생성
- 상태·플랫폼·PM 기준 필터
- 프로젝트 상세 이동
- PM은 빠른 상태 수정과 프로젝트 보관 가능

### 빈 상태

프로젝트가 없을 때만 `첫 프로젝트 생성`을 강조한다. 필터 결과 없음과 구분한다.

## 8. 프로젝트 생성 / 프로젝트 정보 편집

### 목적

프로젝트의 고정 기준을 먼저 등록한다. 업무를 만들기 전에 마일스톤과 플랫폼을 정한다.

### 필수 입력

- 프로젝트 코드
- 프로젝트명
- 적용 플랫폼: PC / 모바일 / 콘솔 / 공통
- 담당 PM
- 시작 기준일

### 선택 입력

- 설명, 외부 협업 여부, 메모
- 기본 플랫폼별 기획·UI·개발 담당자

### 생성 뒤 흐름

1. 프로젝트 저장
2. 마일스톤 입력 또는 템플릿 적용
3. 플랫폼별 담당자 지정
4. 관련 업무 추가

프로젝트 생성만으로 자동으로 과도한 더미 업무를 만들지 않는다.

## 9. 프로젝트 상세

### 사용자와 목적

- 사용자: PM, 팀장, 참여 팀원
- 목적: 하나의 프로젝트에서 마일스톤·직군·업무·담당자 관계를 조율한다.

### 상단 헤더

```text
PC12  하천의2 DLC     [정상] [PC] [모바일] [콘솔]
다음 마일스톤: 데모 빌드 마감 · 2026-10-01 · D-24

플랫폼 담당자
PC      기획 윤도헌 · UI 박지현 · 개발 김개발
모바일  기획 ...
```

### 헤더 행동

- PM·팀장: 프로젝트 정보 수정, 마일스톤 추가, 플랫폼 담당자 편집
- 팀원: 프로젝트 구독/참여 정보 확인, 본인 업무 추가

### 위험 요약 영역

상단 바로 아래에 다음만 우선 노출한다.

- 지연 업무
- 차단 업무
- 미배정 업무
- 인력 부족 직군

정상이면 영역을 접어 화면 높이를 차지하지 않게 한다.

### 일정 조율 표

왼쪽이 날짜, 위쪽이 직군이다.

```text
날짜        | 마일스톤 | 기획 | UI | 개발 | 글비 | 영상 | 제작실 | QA
2026-09-14  | 데모 기획 확정 | 기능 기획 |     |     |      |      |      |
2026-09-16  |           |      | UI 디자인 | |    |      |      |      |
```

- 일 단위 또는 주 단위 전환
- 오늘 열은 강조
- 주말·국가 공휴일은 옅은 배경
- 셀의 업무를 누르면 업무 편집 패널을 연다.
- 빈 셀을 누르면 선택한 날짜·직군을 미리 채운 업무 추가 패널을 연다.
- 표는 수평 스크롤 가능하며 날짜 열은 고정한다.

### 하단 탭

| 탭 | 내용 |
|---|---|
| 전체 업무 | 업무명·담당자·기간·상태를 표 형태로 표시 |
| 마일스톤 | 고정 일정, 진행률, 연결 업무 수 |
| 변경 이력 | 담당자·기간·상태 변경과 경고 확인 기록 |

### 권한

- 팀원: 참여 프로젝트 조회, 본인 업무 수정
- 팀장: 자기 팀 또는 참여 범위 업무 조율
- PM: 전체 수정·배정·마일스톤 관리

## 10. 마일스톤 편집 패널

### 목적

데모 출시·빌드 마감·완전판 출시 같은 고정 기준일을 관리한다.

### 입력

- 마일스톤명
- 날짜
- 플랫폼 또는 공통 여부
- 고정 일정 여부
- 설명

### 기능

- 연결 업무 표시
- 날짜 변경 시 영향을 받는 업무 수와 일정 충돌 사전 안내
- 고정 마일스톤은 삭제 전 확인 필요

## 11. 인력 현황

### 사용자와 목적

- 사용자: PM, 팀장
- 목적: 업무를 누가 받을 수 있는지 판단하고, 과부하를 사전에 막는다.

### 상단

```text
인력 현황
전체 | 여유 | 보통 | 과부하
[팀] [직군] [프로젝트] [다음 가능일]                 검색
```

### 목록

| 열 | 내용 |
|---|---|
| 이름 | 사용자 이름 |
| 팀 / 직군 | 소속과 주 직군 |
| 프로젝트 | 참여는 연한 뱃지, 진행 중은 진한 뱃지 |
| 진행 업무 | 미완료 업무 수 |
| 이번 주 업무량 | 비율, 막대, 여유/보통/과부하 |
| 다음 가능일 | 계산 날짜 |
| 배정 | 업무 배정 진입 |

### 상세 확장

- 4주 업무량
- 현재·예정 업무
- 프로젝트별 업무량
- 해당 사람에게 업무 배정 버튼

### 가용성 계산 기준

- 완료되지 않은 업무의 예상 워킹데이
- 업무별 시작일·마감일
- 사용자별 주간 가능량
- 주말과 국가 공휴일

개인 휴가·연차·병가는 포함하지 않는다.

## 12. 사용자 관리

### 사용자와 목적

- 사용자: 관리자만
- 목적: 계정과 조직 정보, 시스템 권한을 관리한다.

### 목록 열

이름, 이메일, 업무 역할, 관리자 여부, 팀, 직군, 재직 상태, 마지막 로그인

### 필터

미배정 계정, 활성/비활성, 역할, 팀, 직군

### 사용자 편집

- 업무 역할: PM / 팀장 / 팀원
- 관리자 권한 토글
- 소속 팀, 직군
- 활성 상태
- 퇴사 처리

### 퇴사 처리 모달

1. 완료 업무는 유지
2. 진행·예정 업무 목록을 제시
3. 업무마다 `다른 담당자 배정`, `미배정 유지`, `공동 담당자만 제거` 선택
4. 모든 처리 확인 뒤 계정을 비활성화

퇴사 처리 후에도 과거 업무와 변경 이력은 유지한다.

## 13. 공통 시스템 화면

### 알림

- 성공: `업무가 저장되었습니다.`
- 경고: `대상자는 이번 주 과부하 상태입니다.`
- 실패: `저장하지 못했습니다. 네트워크를 확인한 뒤 다시 시도해주세요.`

### 확인 모달이 필요한 행동

- 과부하 상태에서 강제 배정
- 업무 삭제 또는 보관
- 완료 업무 재개
- 마일스톤 삭제·날짜 변경
- 사용자 비활성화·퇴사 처리

### 권한 없음

버튼을 숨기는 것을 우선으로 하고, 직접 URL 접근 시에는 `이 작업을 수행할 권한이 없습니다.`와 돌아가기 버튼을 표시한다.
