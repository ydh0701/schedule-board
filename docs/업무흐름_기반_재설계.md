# 업무 흐름 기반 재설계 기준

> 작성: 2026-08-24  
> 목적: 기존 기획팀·UI팀·전체 마일스톤 파일의 실제 입력 습관을 유지하면서, Firebase 기반 단일 원장으로 전환한다.

## 1. 파일에서 확인한 실제 업무 방식

### PM / 전체 마일스톤

PM은 한 프로젝트의 세부 업무를 직접 모두 처리하지 않는다. 다음을 기준으로 조율한다.

- 프로젝트별 제작 상태, 다음 고정 마일스톤, 특이 사항
- PC / 모바일 / 콘솔 등 플랫폼별 담당 기획·UI·개발 인원
- 타코-글비, 영상, 제작실 등 외부·협업 작업의 일정과 완료 여부
- 시작일, 워킹데이, 공휴일을 반영한 종료일
- 비고에 기록된 변경 사유·의존 관계·위험 신호

### 기획팀 개인 업무표

기획자는 **업무 한 줄**을 직접 만든다. 입력·확인 순서는 다음과 같다.

1. 프로젝트와 세부 업무 묶음을 선택한다.
2. 업무명, 시작일, 예상 워킹데이, 비고를 입력한다.
3. 종료일과 일정상 진행 상태는 자동 계산으로 확인한다.
4. 실제 완료 시 완료 값을 갱신한다.
5. 일자별 타임라인으로 겹치는 업무와 이번 주 업무량을 확인한다.

### UI 업무표

UI도 업무 한 줄 단위로 입력하지만, 기획보다 세부 맥락이 더 필요하다.

- 플랫폼(PC / 모바일 / 콘솔)
- 작업자
- 빌드 버전
- 시스템 또는 화면 영역
- 작업 내용, 시작일, 마감일, 워킹데이
- 현황, 완료 여부, 비고

## 2. 핵심 UX 원칙

1. **표는 입력 방식보다 조회 방식에 가깝다.**
   - 날짜 × 직군 표는 PM·팀장이 일정 관계를 조율할 때 사용한다.
   - 팀원은 표의 셀에 업무를 직접 입력하지 않는다.

2. **팀원은 엑셀 개인 시트와 같은 한 줄 업무 흐름을 사용한다.**
   - 프로젝트 → 업무명 → 시작일 → 예상 워킹데이 → 완료·비고 순서로 입력한다.
   - 자주 쓰는 값만 기본 노출하고, 빌드 버전·시스템은 필요한 직군에서만 펼친다.

3. **일정상 진행과 실제 완료를 분리한다.**
   - 실제 상태: 예정 / 진행 중 / 차단됨 / 완료.
   - 일정 상태: 예정 / 정상 / 임박 / 지연. 오늘·시작일·마감일을 바탕으로 자동 계산한다.
   - 단순 수동 진행률 하나만으로 프로젝트 위험을 판단하지 않는다.

4. **PM은 프로젝트·인력·배정을 같은 기준 데이터로 조율한다.**
   - 한 업무의 담당자·일정 변경은 프로젝트 화면, 팀원 화면, 인력 현황에 동시에 반영된다.

5. **개인 부재 관리는 이 툴의 범위에서 제외한다.**
   - 주말과 국가 공휴일만 자동 비근무일로 계산한다.
   - 휴가·연차·병가·개인 일정은 저장·표시·가용성 계산에 사용하지 않는다.

## 3. 역할과 첫 화면

`관리자`는 시스템 권한이고, `PM / 팀장 / 팀원`은 업무 역할이다. 관리자 여부와 업무 역할을 분리한다.

| 사용자 | 첫 화면 | 가능한 행동 |
|---|---|---|
| 팀원 | 내 업무 | 업무 등록·수정·완료, 본인 업무의 담당자 변경·공동 담당자 추가 |
| 팀장 | 팀 현황 | 자기 팀 업무·업무량·프로젝트 참여 업무 조율 |
| PM | 프로젝트 현황 | 전체 프로젝트, 인력 배정, 일정 조율 |
| 관리자 | 사용자 관리 | 계정 승인, 업무 역할·팀 설정, 퇴사 처리 |

### 팀원 메뉴

- 내 업무
- 참여 프로젝트

### 팀장 메뉴

- 팀 현황
- 내 업무
- 프로젝트

### PM 메뉴

- 프로젝트 현황
- 인력 현황

## 4. 화면별 필요한 정보와 행동

### A. 내 업무 (팀원의 기본 화면)

기본 목록의 한 행:

| 필드 | 기본 노출 |
|---|---|
| 프로젝트·플랫폼 뱃지 | 예: `PC12`, `PC12M`, `PC12C` |
| 업무 묶음 / 업무명 | 필수 |
| 시작일 / 마감일 / 워킹데이 | 필수 |
| 실제 상태 / 일정 상태 | 필수 |
| 완료 체크 | 필수 |
| 비고·참고 링크 | 필요 시 |

보기는 `오늘`, `이번 주`, `이번 달`, `전체`로 전환한다. 업무 추가는 목록 상단에서 열고, 수정은 행을 누르면 연다.

### B. 프로젝트 현황 (PM의 기본 화면)

프로젝트 카드 또는 표에서 바로 본다.

- 프로젝트 코드·이름·플랫폼
- 전체 업무 완료율과 일정 건강 상태
- 다음 마일스톤과 남은 워킹데이
- 지연 / 차단 / 미배정 업무 수
- 참여 직군별 상태 요약
- 플랫폼별 기획·UI·개발 담당자

### C. 프로젝트 상세 (일정 조율 화면)

- 상단: 프로젝트 상태, 다음 마일스톤, 플랫폼별 담당자, 인력 부족 여부
- 본문: **왼쪽 날짜 / 위쪽 업무 트랙** 표
  - 마일스톤, 기획, UI, 개발, 타코-글비, 영상, 제작실, QA, 번역 등
  - 셀은 업무 조회·빠른 수정 진입용이며 주 입력창이 아니다.
- 보조 영역: 지연·차단·미배정 업무, 담당자 변경 이력

### D. 인력 현황 (PM·팀장)

한 사람당 한 줄로 표시한다.

| 정보 | 표현 방식 |
|---|---|
| 이름 / 팀 / 직군 | 텍스트 |
| 담당 프로젝트 | 연한 코드 뱃지: `PC12`, `PC12M` |
| 현재 진행 프로젝트 | 진한 코드 뱃지 |
| 진행 업무 수 | 숫자 |
| 이번 주 업무량 | 비율과 상태(여유 / 보통 / 과부하) |
| 다음 가능일 | 주말·공휴일을 제외해 계산 |

목록을 누르면 현재·예정 업무, 4주 업무량, 재배정 기능을 펼친다.

### E. 업무 배정 전 가용성 확인

- 업무 생성·담당자 변경·공동 담당자 추가 시, 선택한 사람의 **업무량과 일정 충돌을 먼저 계산**한다.
- 계산 기준은 완료되지 않은 업무의 예상 워킹데이, 시작·마감일, 주말·국가 공휴일이다.
- 배정 화면에서는 선택 즉시 다음 정보를 보여 준다.

| 판정 | 표시 내용 | 배정 동작 |
|---|---|---|
| 여유 | `이번 주 40% · 9/03부터 가능 · 마감일 내 완료 가능` | `배정할 수 있습니다`를 기본 확인 문구로 표시 |
| 주의 | `이번 주 80% · 1건과 기간 겹침 · 마감일 내 완료 예상` | 경고를 보여 주고 한 번 더 확인 후 배정 |
| 과부하 / 충돌 | `9/05까지 기존 업무 3건 · 이 업무를 넣으면 마감 2일 초과 예상` | `그래도 배정`을 명시적으로 눌러야 배정 가능 |

- “그래도 배정”을 선택하면 업무는 즉시 대상자의 **내 업무**에 들어가고, 배정자·대상자·시각·경고 사유를 변경 이력에 남긴다.
- 구두로 지원을 조율하더라도 별도 요청함은 필수가 아니다. 실제 확정은 업무 행의 `담당자 변경` 또는 `공동 담당자 추가`로 처리한다.

## 5. 데이터 구조 보완

기존 `tasks`에 다음을 추가하거나 명확히 한다.

```js
tasks/{taskId} = {
  projectId: '...',
  platform: 'pc',                 // pc | mobile | console | common
  workstreamId: 'ui',             // planning | ui | development | taco_business | video | studio | qa | localization
  taskGroup: '데모 준비',
  title: '챕터 리스트 화면 디자인',
  system: '챕터 리스트',           // 직군별 선택 필드
  buildVersion: 'demo',           // 직군별 선택 필드
  assigneeIds: ['uid'],           // 주 담당자 1명 + 후속 공동 담당 확장 가능
  primaryAssigneeId: 'uid',
  startDate: '2026-09-01',
  estimatedWorkdays: 2.5,
  loadUnits: 2.5,                 // 가용성 계산에 쓰는 예상 업무량
  dueDate: '2026-09-03',          // 공휴일·주말 제외하여 계산
  actualStatus: 'in_progress',    // todo | in_progress | blocked | done
  scheduleStatus: 'on_track',     // 자동 계산: planned | on_track | due_soon | overdue
  completedAt: null,
  memo: '',
  links: [],
  milestoneId: null,
  dependencies: [],
  archivedAt: null
}
```

프로젝트 참여 정보와 업무 배정 이력은 업무와 분리한다.

```text
projectMembers/{projectId_uid}    프로젝트 참여 상태·플랫폼·직군
assignmentHistory/{id}            배정·이관·공동 담당 변경 이력과 경고 사유
holidays/{date}                   국가 공휴일
workloadProfiles/{uid}            주간 기준 업무 가능량(기본값 포함)
```

## 6. 구현 순서

1. 기존 데이터 모델의 역할 구분(관리자 권한 vs PM 업무 역할)과 업무 필드를 정리한다.
2. 팀원용 `내 업무`를 엑셀 행 입력 방식으로 재구성한다.
3. 주말·공휴일을 기준으로 마감일·다음 가능일 계산을 통일한다.
4. PM 프로젝트 현황과 인력 현황을 만든다.
5. 프로젝트 상세 일정표를 조율용 조회 화면으로 정리한다.
6. 업무 배정 전 가용성 계산·경고·변경 이력을 추가한다.
7. 기존 임시 더미 데이터와 실제 이관 데이터를 분리하고, 이관 전 검증 화면을 만든다.

## 7. 완료 기준

- 팀원은 기존 개인 엑셀 시트보다 적은 입력 단계로 업무를 등록·완료할 수 있다.
- PM은 프로젝트 현황에서 지연·미배정·다음 마일스톤을 새로고침 없이 확인한다.
- PM·팀장·팀원은 후보자의 다음 가능일과 현재 업무량을 확인한 뒤 배정할 수 있으며, 과부하 배정에는 명시적 경고와 확인이 필요하다.
- 프로젝트 일정표는 직군 간 일정 충돌과 의존 관계를 한 화면에서 확인할 수 있다.
- 프로젝트·업무·인력 정보는 동일한 Firestore 원장에서 실시간으로 일치한다.
